# EUROPA-002D.2b — Readable landmarks and procedural streetscape

### Why the floating POI sign was upside down

The initial 002D.2 markers used a **double-sided Babylon plane** with \`BILLBOARDMODE_ALL\`. Seen from the reverse side, the texture and Bulgarian lettering appeared upside down/mirrored.

The new marker system projects each real POI position through the active 3D camera into **HTML screen-space labels**. It retains the feeling of an in-world label (position moves as the player moves), but the actual text is rendered upright by the browser and cannot be mirrored by mesh orientation. Labels are hidden when the place is behind the player, too far away (>85m), obscured by the screen edge, or one of more than eight simultaneously visible places. The prototype does not yet check line-of-sight behind buildings. Names are inserted as text, never HTML.

### Trees and urban planting

- A low-poly stylised deciduous tree canopy and narrow trunk are generated by deterministic geometry builders.
- Candidate positions follow existing OSM road centre lines and are offset towards roadside verges, with clearance from every mapped road and every imported building footprint.
- Sparse planting uses a cap of **46 trees per active 250m tile**; all trunks and crowns are batched into **two visual meshes per chunk** and disposed with that chunk.
- These are **procedural atmosphere**, not an OSM tree inventory. They deliberately do not add new colliders or claim geographical accuracy.
- No new OSM API fetch or map/chunk regeneration is required.
- No fabricated buildings, street names, or landmarks were added.

### Test on your PC

\`\`\`powershell
cd D:\WebstormProjects\EUROPA-GitHub
git switch feat/europa-002d2-building-coverage-architecture
git pull --ff-only
pnpm test
pnpm typecheck
pnpm build
pnpm dev
\`\`\`

Inspect the floating label from several sides (its Cyrillic must stay upright), follow a residential street and look for varied low-poly trees, then walk across a tile boundary. Watch for FPS drops or \`0 failed\` changing; test that walls still stop the player. Also run:

\`\`\`powershell
pnpm map:coverage --name "TBI Bank"
\`\`\`

This output is essential to determine if the bank is a point-only OSM feature, if there is a nearby imported building, or if source geometry must be upgraded. The current scene **cannot** conjure a genuine missing footprint from a named POI. New physical buildings require raw OSM building ways/relations from a permitted source, or another verified geodata source, then explicit local reimport.
